About this run

What the agent does
Sends out independent sub-researchers to investigate a question from different angles, then synthesises their findings into a single briefing.
The question it was given
"What's the most effective spaced-repetition algorithm for learning a programming language — and what are the trade-offs vs alternatives?"
What counts as "done"
All sub-researchers have reported back and a final synthesis was produced and that synthesis has a confidence score of 70% or higher.
Safety limit (set by us)
Maximum 5 sub-researchers total (3 initial + 2 follow-ups). Maximum 2 synthesis attempts. These caps were designed by us — the agent didn't choose them.
Tools available
Angle picker, sub-researcher spawner, source lookup, finding extractor, report collector, briefing synthesiser.
⚠ Important caveat
This run used a simulated research database. Every real call to the AI model hit an error, so all research data came from pre-loaded mock records. The architecture worked perfectly — the real-data path simply wasn't exercised this run.

Why this goal counted as a real check

A lot of software has goals in the form of wishes: "try to summarise the document," "aim to find at least three results," "see if you can produce a recommendation." These are aspirational. There's no clear moment when the system can compute a yes-or-no verdict on whether it succeeded.

This agent's goal was different. It was a three-part checklist — every item either ticked or not, no judgment call required:

✓ Have all sub-researchers reported back?
✗ Has a final synthesis briefing been produced?
✗ Is the synthesis confidence 70% or higher?

At every single step — after each sub-researcher delivered their report, after the follow-up dispatches, after the synthesis attempt — the agent ran this checklist. The line 📐 [GOAL PREDICATE] is_goal_met(state) → False is the moment of evaluation. False is the right answer every time, because the second and third conditions never cleared.

This is what makes it an agent rather than a loop that just runs a fixed number of times and hopes for the best: the agent always knows whether it's finished, because "finished" is a computable test it runs on itself.

The goal predicate returned False at every step of this run. That's not a malfunction — it's the agent being honest. The checklist didn't clear, so the verdict was False, and the cap eventually made the decision the agent couldn't make for itself: stop.

Agent Spectrum Placement

Where does this agent sit on the spectrum from a simple fixed script to a fully autonomous system?

Workflow (fixed steps) Simple Agent Multi-Step Agent Autonomous Agent ←
If this were a workflow: the script would always dispatch sub-researchers for the same three angles — "technical," "user," and "contrarian" — regardless of the question being asked. A regulatory question would get a technical analysis. A cost comparison would get a user experience angle. The work would be done, but the lenses would be wrong.

What makes it an agent: the line 🎲 [MODEL DECISION] selected: technical, user, contrarian · alternatives: market, regulatory, historical shows the model reading the question and choosing the right angles for it. Different question → different selection. That's not a workflow; that's judgment.

What you could build next

A live research agent

The same architecture, but connected to real sources — Wikipedia, arXiv, a news API. Sub-researchers fetch live content instead of mock records. The architecture doesn't change; only the data source does.

Real perception, live data

An agent that changes strategy when stuck

When a sub-researcher reports a gap, the follow-up gets a different brief — a different source, a different search term, a broader framing. Detecting a gap and dispatching a smarter follow-up: that's the next level.

Adaptive act-step

A fact-checking agent

Three sub-researchers each check the same claim from a different source — do they agree? If two agree and one contradicts, the main agent flags the contradiction rather than averaging it away.

Independent corroboration

An agent that remembers last week's research

After a successful synthesis, the briefing gets saved to a file. Next time the same topic is researched, the agent loads the prior briefing and updates only what changed. It doesn't start from scratch every run.

Persistent briefings across runs
